# 访问与传输（2.5）

```powershell
.\HttpLocalServer.exe --root D:\Share --write-mode isolated --password "你的口令" --strict-host --hotlink-seconds 300 --show-cli-qr
```

右上角的系统、白天、夜间三个图标按钮即时切换配色，偏好保存在当前浏览器。主机“设置”面板可以更新口令、防盗链超时和原有共享设置。空白口令输入保持原口令，勾选“取消登录口令”才会移除登录要求。运行时设置与访问状态只在当前进程中保存；CLI 参数在下次启动时重新应用。

## 登录与主机身份

`--password TEXT` 启用登录，FileTrans 和 Server 的页面、文件、API、预览及流式上传入口都执行检查。口令不回显、不经设置 GET 返回，也不写入配置文件；凭据在当前进程内保存。会话使用随机、HttpOnly、SameSite Cookie，绑定实际 TCP IP，最长 24 小时。修改口令使旧会话和旧预览授权失效；应用修改的主机浏览器得到新会话。MCP 使用原有独立 Bearer 凭据与主机检查。

每个实际 IP 每轮有 5 次机会，失败后等待依次为 120、240、480……秒，上限 86400 秒（24 小时）。封禁期间重复提交，包括正确口令，都不会推进轮次或延长截止时间。等待结束获得下一轮 5 次机会；登录成功或主机手动解锁会重置该 IP 的失败记录。主机“设置 → 登录封禁 IP”查看倒计时并解锁。已有有效会话不会因同 IP 的另一个登录尝试被注销。

`--strict-host` 只允许命令行启用。启用后仅源地址精确为 `127.0.0.1` 或 `::1` 才是管理员，`localhost` 通过其实际连接的回环地址判定；本机的局域网 IP、`127.0.0.2`、代理头都不能取得主机身份。未启用时维持原规则：回环或当前网卡地址作为主机。主机按钮仅对管理员显示，管理 API 独立复查身份与写令牌。

独立 IP 模式下主机可在整个共享目录上传、复制与管理，免逐 IP 额度和独立目录数量限制；远端继续只写自己的目录。单文件上限、只读模式和显式只读挂载仍是主机配置的有效规则。

HTTP 本身不提供链路加密；此口令是访问控制，不是 TLS 的替代。2.6 可选 mbedTLS HTTPS 见 [HTTPS 配置](https.md)。地址、口令、封禁和身份均不信任 `X-Forwarded-For` 等转发头。

## 防盗链与预览

`--hotlink-seconds SEC` 设置空闲秒数，默认 0 关闭，最大 86400。主机面板可动态修改。启用后，下载需要浏览器访问会话；外站引用与没有会话的直接链接会被拒绝。页面交互和实际传输刷新活动时间，后台目录监听、提供方空闲轮询不会无限续期。持续大文件传输逐块续期，音视频 Range 流量也续期。

空闲超时后复制下载 URL 不会恢复权限。返回页面执行下载会重新激活当前浏览器会话；“更多 → 恢复下载会话”也可手动激活。播放器的播放和定位操作先更新会话再发起后续请求。口令会话本身过期时返回登录页。

网页继续在不继承主站权限的沙箱内运行。启用登录或防盗链后，预览跳到绑定 IP、会话和设置版本的临时 `/preview-assets/…` 地址；它只读取可共享文件，不能调用管理、浏览 API 或写入接口。相对 CSS、脚本、图片、媒体等请求沿此地址传输，相关的根路径引用在不超过 2 MiB 的 HTML/CSS/JavaScript/SVG 中重写。超大文本资源、动态拼接的绝对地址、外部网站资源或不兼容沙箱的网页不保证完整运行。媒体与大文件仍按块传输，不整文件缓存在网页内存中。IE11 继续禁用 HTML/SVG 主动文档预览，保留安全下载降级。

## 复制粘贴与挂载保留

文件或文件夹右键“复制”，切换标签后在当前目录的更多菜单、空白处右键或目标文件夹右键“粘贴”。支持 Ctrl/Cmd+C、Ctrl/Cmd+V；文本输入框保留浏览器自己的复制粘贴。剪贴板在应用标签间共享，同源的其他浏览器标签也会同步；原生剪贴板中的文件可粘贴上传。

普通目标由 C++ 存储线程逐块复制并通过私有临时文件原子发布，源文件固定版本，保留 COW 读者，绝不覆盖已有同名文件。浏览器挂载目标使用 256 KiB 范围读取与写入块。目录逐项复制，保留层级和隐藏内容，一次最多 10000 项、64 层。取消或失败保留已完成文件；单个未发布文件不会当作完成文件展示。服务端复制实际写入的字节计入逐 IP 写入额度；独立模式主机豁免。

浏览器挂载已完成的副本直接位于选定的共享路径，卸载后可继续浏览、下载，重启也保留。卸载时未完成的上传会停止发布，已经打开的下载句柄可继续读取完整版本。详见 [挂载与上传额度](mounts.md)。

## 地址二维码与压缩

“更多 → 访问地址与二维码”打开地址弹窗，优先推荐普通局域网接口地址，并列出当前监听地址族的其他候选。推荐使用接口类型和地址范围启发式排序，不能替代网络可达性检查；可手动选择其他接口。二维码只编码网站 URL，不包含口令或会话令牌。

CLI 默认列出推荐和其他地址；仅 `--show-cli-qr` 才绘制二维码。Win7 控制台用原生颜色与半块字符，Unix 交互终端用 ANSI；重定向输出使用无终端控制码的 ASCII 图案。二维码编码器为内置 C++ Nayuki v1.8.0，保留 MIT 声明，兼容项目 Apache-2.0 与闭源商业分发。

HTTP gzip 默认开启，可用 `--no-compression` 关闭、`--compression` 显式开启。按 `Accept-Encoding` 的 gzip、通配符和 q=0 协商。嵌入页面、图标使用预压缩数据，JSON 与较小文本使用有界缓冲，较大可压缩文件逐块 gzip，HTTP/1.1 使用 chunked，HTTP/1.0 关闭连接标记结束。媒体、压缩包等不再重复压缩；所有 Range 请求保留 identity 编码、字节偏移与续传校验，附带 `Vary: Accept-Encoding` 区分表示。

## 核验

自动检查：`tests/access_integration.py`（OpenCV 可用时独立解码二维码）、`tests/clipboard_test.cjs`、CTest 的登录退避策略检查，以及原有挂载、COW、目录监听与大文件 HTTP 套件。Mac 继续只检查源码适配，不构建或运行测试。

IE11 手工步骤：

1. 启动 `--password test --strict-host --hotlink-seconds 10`，用准备好的 `tools/LaunchIE.exe` 打开 `http://127.0.0.1:8000/`；正确登录后检查右上角三个图标及设置按钮。
2. 从另一个 IP 连续输错 5 次，确认出现约 120 秒等待；继续提交不会增加剩余时间。在主机设置中解锁后再次登录。
3. 在两个应用标签间复制 TXT 和含子目录的文件夹，确认同名冲突与取消提示；复制粘贴文本框应照常工作。
4. 打开 URL 二维码弹窗；下载一个大文件，检查超时后仍有流量的传输继续，完全空闲后再次点击下载可恢复。暂停音视频后等 10 秒再播放、拖动进度条。
5. 使用响应头检查页面是否为 gzip，带 Range 的下载应为 206 且没有 Content-Encoding。HTML/SVG 预览保持 IE 的安全降级；现代浏览器另核验 CSS、脚本、图片与新窗口音视频。
