# PCDN 与专用 P2P 下载

2.9.0 将两件事分开：**默认下载始终是普通 HTTP 下载**；PCDN 总开关开启后，有能力的访问页面默认静默充当发送者，右键才可以选择专用 P2P 下载。不会询问下载者是否共享，也不在下载完成后显示“停止分享”流程。

## 主机设置

```powershell
.\HttpLocalServer.exe --root D:\Share --p2p
.\HttpLocalServer.exe --root D:\Share --p2p --p2p-cache-mb 32 --p2p-cache-seconds 3600
```

PCDN 总开关默认关闭，主机“设置”中可统一开启或关闭发送与 P2P 入口，并动态设置：

- **每页缓存上限：0–64 MiB，默认 64 MiB**。同一页面的所有文件共用总额度，0 立即释放缓存、停止充当默认发送者。
- **缓存空闲有效期：1–86400 秒，默认 3600 秒**。主机核实同版本文件的节点协商，或节点实际收发、下载进度推进时续期。纯空闲轮询不续期。

每个已校验块按文件路径和版本隔离。在额度内保留最近使用的内容，超额淘汰旧块；到期开始清理，前台正常运行时最多约五秒检查一次，读取前也检查。浏览器冻结后台页面时计时器可能延迟，恢复运行后清理。改变文件版本不会复用旧内容。这里的额度限制 **PCDN 保留的正文块**，不包括浏览器自身、临时传输缓冲、哈希元数据或下载输出占用。

缓存不随一次下载任务结束就消失；之后主机分配同版本文件时可复用。不会预读整棵共享目录。被动发送者首次收到缺块请求时才从主机拉取、校验并缓存，同块拉取合并；首次复制本身仍消耗主机流量，后续缓存复用才减少主机出口。

## 挂载提供方参与分发

浏览器挂载方持有本地文件句柄，是天然内容源。专用 P2P 票据和加入只读取来源元数据，不再等待整个文件上传完成。页面通过挂载密钥及实际 IP 向主机证明所有权，主机优先分配来源页面；单纯同 IP 或伪造挂载 ID 不能获得源身份。

来源页面收到获准请求后直接读本地 1 MiB 切片，校验后经 WebRTC 发送，避免主机下行。它最多承担 4 个活跃文件，所有任务共用整页缓存、带宽与 2 个并发发送额度；页面关闭发送会一次撤销全部源分配。安全上下文/目录选择 API 的能力限制仍适用，HTTP 客户端可以接收 HTTPS/本机挂载方已有的内容来源。

完整主机副本形成前，哈希权威来自已经注册的挂载提供方：主机通过受认证的任务核实文件路径、来源版本与分片清单。其他缓存节点不能提交清单。完整副本存在时可由主机计算校验值。哈希缓存按逻辑路径和版本隔离，最多 4 个活跃计算/来源任务；同一页清单请求合并，防止多人下载重复扫描。挂载提供方本身是该共享内容的信任来源，校验用于防止传输损坏、其他节点污染和串版本，并非验证来源者本身诚实。

挂载目录仍缓慢复制到主机；普通访问或 P2P 回源时优先完成被访问文件的主机副本，再按 Range 分发。P2P 直接发送不会取消后台复制。断开、卸载后已上传完成的内容保留；旧来源协作在卸载/更换后失效，客户端可重新取得普通下载链接。没有完整副本且来源离线时不能凭空补齐缺块。每 IP 上传额度统计上传到主机的字节；节点直传不计入主机上传额度。

来源心跳、回复使用独立的 32 个控制请求额度，副本上传另有 8 个额度，避免等待来源的下载/哈希占满资源后把来源本身堵住。正文缓冲仍受全局内存池限制。

## 访问者操作

工具栏“下载”、通常的文件下载操作仍直接交给浏览器原生下载器，不会自动切换到 P2P。符合浏览器能力和文件大小条件时，右键和“更多”另提供“P2P 下载”，用于有节点缓存或需要分担流量的场景。

PCDN 的发送不需要额外确认。页面左栏及“更多”可关闭本页面发送；一次关闭对这个网页后续任意多次事件有效，不写入 localStorage、sessionStorage 或 Cookie。刷新或重新打开页面恢复默认开启；主机设置更新不会重置仍打开页面的选择。关闭发送也不妨碍手动选择 P2P 接收。关闭页面停止该页面的参与并释放缓存。

## 特大文件与内存

专用 P2P 的输出自动按浏览器能力选择，无共享确认弹窗：

1. 支持 `showSaveFilePicker` 且处于安全上下文时，直接打开浏览器标准保存窗口，选择本地文件。随后按 1 MiB 分片验证并写盘；下载输出不需要整文件驻留内存。选择已有文件会逐块验证后续传。
2. 没有安全本地写入 API 时，只提供有界内存暂存：桌面最多 32 MiB、窄屏最多 16 MiB。浏览器提供 `deviceMemory` 时可进一步下调，最低 4 MiB。超出当前上限的文件不显示 P2P 下载入口，继续使用普通下载。

内存提示不是精确可用内存测量。内存很紧张、文件特大或需要浏览器下载器完整的后台管理能力时，应使用默认普通下载。P2P 不作为这些情况的通用推荐。

本地写入 API 通常需要受信任 HTTPS 或回环安全上下文，并非所有浏览器提供。HTTP 和 HTTPS 均可进行 WebRTC 节点传输；普通局域网 HTTP 缺少 WebCrypto 时使用项目自有 SHA-256，优先 Worker、其次分时计算。但远端普通 HTTP 不能因此获得本地写入权限，仍受小文件暂存上限限制。IE11 或无 WebRTC 的浏览器保留普通下载，不提供 P2P 入口。

暂停、取消、完成及可处理的错误关闭本地写入流并提交已有进度。浏览器的 COW 写入实现可能需要额外磁盘空间，检查点从 32 MiB 起按四倍间隔增长，避免反复复制不断增长的文件；恢复较大已有文件时跳过自动检查点。崩溃或断电可能丢失最后提交后的进度。此功能不承诺零拷贝续传。当前支持非空、最大 1 TiB 的普通文件、原生挂载文件及浏览器持续挂载文件；目录保持原有下载方式。

## CLI 参数

| 参数 | 默认 | 含义 |
|---|---:|---|
| `--p2p` / `--no-p2p` | 关闭 | PCDN 总开关 |
| `--p2p-cache-mb N` | 64 | 整页保留缓存，0–64 MiB |
| `--p2p-cache-seconds N` | 3600 | 空闲有效期，1–86400 秒 |
| `--p2p-seed-seconds N` | 3600 | 上一参数的兼容别名，含义改为空闲有效期 |
| `--p2p-peers N` | 4 | 每页面文件任务的连接上限，1–8 |
| `--p2p-upload-kbps N` | 4096 | 整个页面共用的分享 KiB/s；0 不限 |

一个页面同时执行一个主动 P2P 下载，主动下载期间不额外运行被动任务；空闲挂载提供方最多承担 4 个活跃文件，其他被动页面最多 1 个文件。所有任务共享缓存、带宽和最多 2 个同时发送任务。被动任务可在不同文件之间切换，已缓存的其他文件仍受整页额度和各自有效期约束。主机最多登记 512 个文件节点、每 IP 32 个、每文件版本 128 个，另有 512 个被动页面、每 IP 32 个；租约 20 秒。信令、发现列表、发送缓冲和哈希计算均有预算，不使用外部 STUN / TURN。

## 校验、权限和回源

主机按需提供 SHA-256 分片哈希，接收方验证后才写入或共享。错误块、缺块、节点离线或网络隔离会回退到固定文件版本的主机 Range。主机最多缓存 8 MiB / 4096 页哈希，空闲五分钟淘汰，最多四个计算任务并行。

节点身份绑定真实 TCP IP、浏览器 Cookie、随机密钥和访问策略版本；同源、令牌、登录及防盗链检查保留。缓存有效期与防盗链会话分别计算：缓存未到期不代表仍可绕过登录或防盗链传输。主机关闭总开关、口令变更或文件变化会停止旧协作；已被接收的数据无法撤回。

`/api/status` 的 `p2p.reportedPeerBytes` 是客户端上报参考值，不是可信账单。没有可用缓存、UDP 被隔离或浏览器禁止 WebRTC 时，P2P 可能全部回源且比普通下载更慢。

验证记录见 [verification/release-v290.json](verification/release-v290.json)。本地文件 API 的窗口和超大文件长时间行为尚需目标浏览器实测；自动测试中的句柄替身不等于真实保存窗口验收。macOS 本轮按要求不构建、不测试。
