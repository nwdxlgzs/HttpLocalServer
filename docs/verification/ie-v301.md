# IE11 增量核验

本轮自动检查通过 ES5 解析、缺少现代 API 时的整页启动；这些检查不替代真实 IE11。

1. 启动 `HttpLocalServer --write-mode shared`，用 IE11 打开页面。确认列表、任务中心和普通下载可用，挂载目录/直接保存本地目录等不可用的浏览器功能不出现。
2. 上传多份文件，将任务中心并行数改为 1。在运行中暂停一个任务，确认后面的任务可以继续；恢复后确认原任务继续上传。也测试尚在排队的任务暂停、恢复。
3. 用两个文件制造同名目标，批量移动并选择“逐项询问”。确认没有未经询问直接跳过，选择保留两份后两个文件均存在。确认弹窗打开时修改目标文件，再选择替换，应收到冲突，目标的新内容保留。
4. 下载小目录 ZIP，检查中文名称、子目录、空目录和内容；冻结配置不能进入 ZIP。将 ZIP 与上传一起排队，检查公共并行数生效。IE 的内存 ZIP 关闭页面后需要重新发起。
5. 复制含多个文件的目录，暂停后恢复；断网造成失败后重试，检查已完成的项目保留。支持保存检查点时，重开页面后任务中心提供继续入口；若存储不可用，应显示保持页面打开的提示。
6. 用 `HttpLocalServer server --root <网站目录> --write-mode shared`，打开 `/_hls/` 重复上述操作，确认网站原有托管地址仍能访问。

磁盘 ZIP、直接目录保存、浏览器持续挂载和落盘 P2P 的授权/句柄恢复，需要支持 File System Access API 的浏览器验收，不在 IE11 的能力范围内。
