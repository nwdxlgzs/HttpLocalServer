# IE11 人工核验：3.3.0

本次已运行 ES5 静态检查及 Chromium 缺失现代 API 的兼容测试，未启动真实 IE。macOS 仍按要求仅保留源码适配，不做实机测试。

在准备好的临时共享目录启动：

```text
HttpLocalServer-windows-x64.exe --no-config --root D:\HLS-Test --port 8000 --write-mode shared --zip-preview host
```

使用 `tools/LaunchIE.exe` 打开 `http://127.0.0.1:8000/`，核验：

1. 有后缀与无后缀图片均能选择后预览；错误后缀 ZIP 选中后出现 ZIP 预览动作。
2. TXT、JS、日志等文本能预览；“编辑文本”使用普通编辑器，保存中文，刷新后内容一致。用另一窗口先修改同一文件，再保存旧内容，应提示冲突并保留编辑内容。
3. Markdown 在普通目录和 ZIP 内均显示标题、表格、关联图片与包内文档链接。原始 HTML 显示为文字；压缩包内网页在 IE 保持下载降级。
4. Word 基本预览可连续向下滚动，文字、表格和常见内嵌图片可见；PPT / Excel 使用兼容预览，文字可选取并复制。该路径不保证桌面 Office 的完整排版。
5. PDF 可以连续滚动，附近页面出现画布和文字；页码、缩放和复制可用。图片复制优先兼容 HTML，失败时可保存 PNG。
6. 显示隐藏项目后，`.hls-state-*` 与配置同样显示斜纹冻结项；双击、下载、删除、复制均不能访问内部内容。
7. 右上角主题切换、标签关闭与导航、目录列表滚动分页继续可用。

默认配置延迟生成需要另起一个不含 config.json 的工作目录，以不带 `--no-config` 的方式启动：启动后不应生成配置及配置锁；修改主机设置后才保存 config.json，文件继续冻结。显式指定不存在的 `--config PATH` 则会初始化，这是有意保留的行为。
