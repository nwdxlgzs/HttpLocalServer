# IE11 增量核验（3.2.0）

此前已经核验通过的列表、普通下载和写入功能不必重做。本轮没有替你执行 IE 实机核验；以下是新预览入口的人工清单。

1. 启动 `HttpLocalServer --zip-preview client --root <测试目录>`，通过准备好的 LaunchIE.exe 打开页面。测试目录放入普通 ZIP、DOCX、PPTX、XLSX 和 PDF。
2. ZIP 预览在管理器新标签中打开。根目录、子目录、返回、超过 100 项的滚动加载、单项下载应可用。包内网页会提示下载后打开，这是 IE 的安全降级。
3. DOCX 显示正文/表格，PPTX 显示幻灯片文字且可以翻页，XLSX 显示工作表值、可以切换工作表/数据页/列范围。页面应明确标注基本预览。
4. 用鼠标选择文字或表格，点击“复制”，粘贴到记事本。Excel 基本预览的表格也应能选择、复制。不要要求其复杂 Office 版式与现代浏览器相同。
5. PDF 应显示图形和可选择文字；试验翻页、适合宽度、放大缩小、页内查找、复制。旧浏览器 PDF 上限 32 MiB。加密 PDF 会询问密码。
6. 用主机设置切换 ZIP 为主机模式，再测试目录、包内文件下载。主机模式不会执行 IE 包内网页。
7. 打开至 12 个内部标签，再打开 ZIP：应提示先关闭多余标签，不能静默关闭旧标签。关闭一个后可重新打开。
8. 切换白天/夜间，预览工具栏跟随；Office/PDF 纸张内容保留白色以避免改动文档本身的颜色。
9. 关闭主机预览总开关：现有文档应停止预览，重新打开入口被拒绝。独立预览窗口在下一次策略检查时停止。
10. 关闭预览标签后，确认相关 Worker 不继续处理；重新打开同一文件能正常加载。

不要为了人工测试自行解压未知或恶意压缩包。自动对抗测试使用有界生成的样本，入口为 `tests/zip_preview_integration.py` 与 `tests/zip_codec_test.cjs`。
