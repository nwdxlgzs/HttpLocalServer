# 3.1.0 IE11 增量核验

此前 IE 验收由用户完成。本轮已通过 33 份 ES5 源码、缺少现代 API 的启动与能力降级检查；以下用于新增传输恢复路径的人工确认。

1. 启动 `HttpLocalServer.exe --no-config --root <测试目录> --port 8001 --write-mode shared`，用 IE11 标准文档模式访问。列表、标签、搜索、配色和普通下载应保持可用；不支持的本地文件系统 API 入口隐藏。
2. 下载一个包含大文件、中文名、空文件和空目录的文件夹。IE 路径应在页面执行 ZIP 压缩，使用主机私有暂存，最后交给浏览器下载；页面不构造整个 ZIP 的 Blob。
3. ZIP 打包中途刷新页面，在任务中心继续原任务；完成后用系统解压工具核对全部内容。主机私有暂存到期前，浏览器下载管理器可以通过 Range 继续最终 ZIP 文件。
4. 普通上传到一半暂停，刷新并重新选择原文件后恢复。先尝试同名同大小、仅中部不同的文件，应拒绝拼接；选择原文件应继续已确认前缀之后的数据。
5. 复制大文件到另一目录，中途刷新，在任务中心恢复；原目标仅在完整发布后出现，不覆盖已经被其他人修改的目标。
6. 从另一台现代浏览器建立读写挂载。IE 上传到该挂载，刷新重选原文件恢复；确认提供方文件与主机副本完全一致，私有暂存不会出现在共享列表。
7. 将文件移入、移出浏览器挂载；同名时选择保留两份或确认替换。传输中改变源文件，应保留变化后的源；新增、跳过或冻结的文件应留在原目录。
8. 浏览器原生下载只显示“已发起”，不伪造完成状态。取消托管任务后暂存应回收；浏览器对文件系统的授权不会被页面刷新自动绕过。

没有本地文件系统写盘 API 的浏览器使用服务器 ZIP 暂存；本地目录分块保存、原生磁盘 ZIP 和磁盘 P2P 需要支持这些 API 的现代浏览器。macOS 按用户要求未运行测试；Windows 7 真实系统的兼容性仍需对应设备确认。
